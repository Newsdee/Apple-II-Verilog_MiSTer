# cpu_65c02 vs R65Cx2 — cycle-level comparison of the r65 stimulus pair

Date: 2026-09 (analysis of traces generated by `run_divergence.ps1`);
corrected 2026-09-03 per Priority 2 of `CPU_COMPARISON_RECOMMENDATIONS.md`
(narrowed verdict, precise check names, architectural vs bus-protocol
separation, BRK/RTI coverage marks, IRQ vector fix, park-loop explanation,
whitelist-linked delta table).
Scope: the **r65c02 stimulus pair** — new core `rtl/new_cpu/cpu_65c02.sv`
versus the Verilog golden `rtl/R65Cx2.sv` under the shared 64K r65 image.

Verdict up front (narrowed to what this evidence supports): **on the covered
directed r65 stimulus, the new core and R65Cx2 execute the same
instruction-fetch sequence and reach the same architectural state and final
RAM state, with documented bus-visible cycle differences.** Concretely:

- *Architectural equality* (holds): identical 1504/1504 opcode-fetch
  sequence, equal end-of-trace registers (modulo the constant P_B),
  equal interrupt stack bytes and vectors, and **final write-map
  equality** — replaying every write transaction into a 64K image with
  last-write-wins gives identical images at all 33 written addresses.
- *Bus-protocol equality* (does NOT hold, documented): per-instruction
  cycle counts differ on three opcode classes (six instances), and the
  golden emits one extra old-value **write strobe** per RMW instruction
  (28 in this trace). Extra reads and writes are observable by
  memory-mapped devices even when final RAM is identical; they are treated
  here as behavioral differences, not sampling noise. The maintained gate
  for both halves is `semantic_compare.py` + `semantic_whitelist.txt`
  (Priority 1); the delta table in §4.1 shares IDs with that whitelist.

## 2. Methodology

Row-aligned field comparison is **not sufficient** for this pair: the cores
have different pipeline phase conventions and (as it turned out) different
cycle counts on a few opcodes, so rows drift apart in content. The analysis
therefore proceeds in six steps, each discarding or explaining a class of
apparent difference before moving to the next.

### Step 1 — raw row-aligned census, then reclassification

A naive field-by-field diff of the two CSVs reports thousands of differences;
almost all are sampling artifacts (Section 3). Each differing row is
classified:

- `ADDR` or `DI` differs → candidate real difference (or phase drift, see Step 2)
- only `RW` differs, with `ADDR`+`DI`+`DO` equal → **write-cycle sampling
  edge** (artifact): the two cores put the write strobe on different edges of
  the same bus cycle
- `DO` differs while `RW=1` → **stale output data** (artifact): `DO` is only
  meaningful on write rows (`RW=0`)

Result in the in-phase region (reset through G cycle 542, before any
cycle-count divergence): `ADDR` and `DI` are identical on **every** row; the
only row-level differences are 16 RW-only flips. Across the full trace there
are 12 rows where `ADDR`+`DI`+`DO` all match but only `RW` differs.

### Step 2 — instruction alignment by fetch events

Instruction *i* in G is aligned with instruction *i* in N by pairing the
*i*-th `SYNC=1` row (opcode fetch) in each trace and comparing the fetch's
`ADDR` and `DI` (the opcode byte). This is robust because:

- The **`PC` column must not be used** for alignment: G's `PC` lags by one
  row on the first fetch after reset and after taken branches, and N's
  register columns update one row earlier than G's. Fetch `ADDR` on
  `SYNC=1` rows is unambiguous in both traces.
- If the instruction streams ever diverged (wrong opcode executed), the
  pairing would show an opcode/address mismatch at that point.

Fetch selection uses **`SYNC=1` alone**, not `SYNC=1 && SYNC_IRQ=0` as
originally recommended: the two TBs mark interrupt entry differently. G
asserts `SYNC_IRQ` across the *entire* entry sequence (7 rows per
interrupt: tail NOP, three stack pushes, two vector reads, entry fetch),
while N marks only the entry fetch — plus the first fetch after reset,
which only N double-marks. Strict filtering therefore removes 2 rows from G
but 3 from N (1502 vs 1501) and misaligns the pairs; `SYNC=1` alone gives
1504/1504 in both, and the `SYNC_IRQ` rows are reported separately as
interrupt-entry annotations. (This is implemented and documented in
`semantic_compare.py`.)

Result: **1504 fetch events in each trace, 1504/1504 aligned pairs, zero
opcode/address mismatches.** The cores execute exactly the same program.
(Composition caveat — see §4.2: 766 are non-park fetches, each at a
distinct address; 738 are repetitions of the final park loop.)

### Step 3 — per-instruction cycle-count diff

For each aligned pair *i*, instruction length = (fetch cycle of *i+1*) −
(fetch cycle of *i*). Lengths are bucketed by opcode + addressing mode
(decoded with the classic 6502 encoding table used by the r65 harness).

Result: every opcode/mode class has identical G/N lengths **except the
three §4.1 opcode classes** (the four shift/rotate `.ax` forms and both
indirect JMPs — six opcodes, one instance each). Cumulative delta (G − N fetch cycle) walks
0 → +1 → +2 → +3 → +4 across the four `.ax` shift instructions at `$0672`–
`$067B`, then back to +2 after the two indirect JMPs at `$06C0`/`$06CA`, and
stays +2 to the end of the trace (last aligned fetch: G cycle 3999, N cycle
3997, both at `$0908`).

### Step 4 — state comparison at instruction boundaries, with the verified one-fetch skew rule

Registers/flags are compared at aligned instruction boundaries. The
original "±1-row update skew" tolerance was replaced on 2026-09-03 by a
precise, fully verified rule (implemented in `semantic_compare.py`):

- **One-fetch state skew**: for every non-SP column (A, X, Y, P_N, P_V,
  P_D, P_I, P_Z, P_C), the state on G's fetch row *i* equals the state on
  N's fetch row *i−1* — i.e. G's architectural columns lag by exactly one
  fetch. Verified over all 1503 boundaries with **zero mismatches**.
- **SP**: matches under the same shift at 1489/1503 boundaries; the 14
  unshifted cases occur exactly after stack-touching instructions (PHA, PLA,
  PHX, PLX, PHY, PLY, PHP, PLP, JSR, RTS) and at the two interrupt-entry
  fetches where the preceding instruction was a NOP. All 14 are reported,
  not silently accepted.
- **PC column**: raw boundary dPC ∈ {0, 1} (842×0, 659×1); the only other
  values are in-transition sampling after control-flow transfers — RTS at
  `$0912` (dPC=64681) and BRA at `$08fd` (dPC=65286). Architectural PC is
  proven by fetch-address identity (Step 2) plus final-row equality, not by
  the raw column.

Every apparent SP/Z/N/C/I boundary difference found in the original manual
pass turned out to be exactly this skew — e.g. after `PHA @ $05A9` both
cores write `5A → $01FD` and SP→`FC`, sampled one row apart; after
`TSB $80 @ $0640` both end with Z=1.

### Step 5 — final write-map equality (NOT transaction equality)

Independently of cycle alignment, replay **every write transaction**
(`RW=0` rows: `ADDR ← DO`, last-write-wins) in each trace into a 64K array
and diff the two final images. This is phase-insensitive: it catches any
real final-value divergence anywhere in the trace regardless of the ±2-cycle
drift. It is named **final write-map equality** and must not be read as
transaction equality — the ordered per-instruction write-event comparison
(live in `semantic_compare.py`) is a separate, stronger check: G emits 98
write rows vs N's 70, differing by exactly the 28 whitelisted RMW
old-value pre-writes (see §4.1).

Result: **33 distinct addresses written in each trace; final values
identical at all 33.** (Includes the `$0A00`/`$0A78` shift targets, all
stack writes, and the interrupt pushes.) A measurement caution recorded
here: reconstructing the map with first-write-wins (e.g. `dict(reversed(...))`)
produces spurious diffs at `$0008`/`$0A78`; forward last-write-wins
iteration gives equal maps.

### Step 6 — HDL cross-check of every surviving difference

Each real difference from Steps 3–5 is located in both sources so the report
states *why* it exists, not just *that* it does:

- G: `rtl/R65Cx2.sv` (state machine + opcode table; B-flag comment block at
  ~line 655, `aluModeP` push composition)
- N: `rtl/new_cpu/cpu_65c02.sv` (`reg_p` definition, `int_active`,
  `do_writeback(R_P)`, and the `S_ABS_HI`/`S_IDX_FIX`/`S_READ`/`S_RMW_M`
  timing paths)

## 3. Trace artifacts (must be excluded before interpreting any diff)

| Artifact | Rule |
|---|---|
| `DO` on read rows is stale or actively driven | Ignore `DO` whenever `RW=1` |
| Write-strobe phase differs between cores | Rows with equal `ADDR`+`DI`+`DO` but flipped `RW` are the same bus event, not a difference |
| G's `PC` column lags one row after reset / taken branches | Never align on `PC`; use fetch `ADDR` on `SYNC=1` rows |
| N's state columns settle one fetch earlier than G's (one-fetch skew, Step 4) | Compare `golden_fetchrow[i]` against `new_fetchrow[i-1]`; SP may match unshifted at the 14 reported stack-op/interrupt-entry boundaries; raw PC column accepts dPC∈{0,1} plus reported control-flow exceptions |
| After the first cycle-count divergence (G cyc 542), rows are phase-drifted by 1–2 cycles | Any row-aligned comparison beyond that point is meaningless; use Steps 2, 3, 5 instead |

## 4. Results

### 4.1 Cycle-count differences — the only real behavioral delta

Three opcode classes, six instances in this trace (one instance each of the
four shift/rotate `.ax` forms plus two indirect JMPs). The **whitelist ID**
column names the matching entry in `semantic_whitelist.txt` (shared with
`semantic_compare.py`); delta = G − N cycles:

| Whitelist ID | Opcode (instances) | G cycles | N cycles | G bus pattern | N bus pattern | Real silicon |
|---|---|---|---|---|---|---|
| `LEN +1 1e 3e 5e 7e` + `RMW_PREWRITE_GOLDEN` | ASL abs,X `$1E` @0672, ROL `$3E` @0675, LSR `$5E` @0678, ROR `$7E` @067B (target `$0A78`) | **7** | **6** | fetch×3, R, R, **W(old)**, W(new) | fetch×3, R, R, W(new) | 6502: 5 (R,W); 65C02S: 6 (R,R,W) → N matches W65C02S |
| `LEN -1 6c` | JMP (indirect) `$6C` @06C0 (ptr `$00F0`) | **5** | **6** | fetch×3, R lo, R hi | fetch×3, R lo, **R lo (again)**, R hi | 6502: 5 no-wrap; 65C02S: fixed 6 → each matches one |
| `LEN -1 7c` | JMP (abs,X) `$7C` @06CA (ptr `$00E8`, X=0) | **5** | **6** | fetch×3, R lo, R hi | fetch×3, **R next-opcode ($06CD)**, R lo, R hi | 6502 and 65C02S: 6 → G is short one here |

The `RMW_PREWRITE_GOLDEN` whitelist entry covers the full read-modify-write
family (ASL/ROL/LSR/ROR, INC/DEC, EOR, TSB, AND-bit in zp/zp,X/abs/abs,X
forms — 36 opcodes). In **this** trace 28 RMW instructions exercise it:
TSB `04/0c/14/1c` @0640–064d, ASL `06/0e/16/1e`, ROL `26/2e/36/3e`,
LSR `46/4e/56/5e`, ROR `66/6e/76/7e` (zp/abs/zp,X/abs,X forms @0656–067b),
DEC `c6/d6/ce/de` and INC `e6/f6/ee/fe` (@0680–0691). EOR and AND-bit are
whitelisted for future stimuli but not exercised here. The entry permits
exactly one extra golden write to EA whose data equals a value read within
the same instruction, immediately before the matching new-core writes —
anything else fails the run.

Concrete example (ASL abs,X, target `$0A78`, old value `5B`, new value `B6`):

```
G (7 cycles)                          N (6 cycles)
c542 R $0672 1e   SYNC                c542 R $0672 1e   SYNC
c543 R $0673 00                              c543 R $0673 00
c544 R $0674 0a                              c544 R $0674 0a
c545 R $0A78 (DI=5b)                        c545 R $0A78 (DI=5b)
c546 R $0A78 (DI=5b)                        c546 R $0A78 (DI=5b)   ; 65C02 second read
c547 W $0A78 DO=5b   <- extra write of OLD c547 W $0A78 DO=b6
c548 W $0A78 DO=b6
```

Hardware-observable consequences: G emits an **extra real write strobe** on
the shift/rotate abs,X targets (carrying the pre-shift value — harmless to
RAM, visible as a WE pulse), N emits an **extra read strobe** on the pointer
low byte for JMP (indirect), and N reads the following opcode byte during
JMP (abs,X). Final memory is unaffected in all cases (verified in Step 5).

Everything else matches in cycle count — verified per instance for the
branch family (not-taken = 2, taken = 3, page-crossing taken BRA = 4, which
matches real silicon exactly in both models). The classes where *both*
models deviate from a 6502 in the same way: plain-abs RMW = 6 (6502: 5;
consistent with the 65C02's extra pre-write read that N implements
explicitly in `S_RMW_M`), and INC/DEC abs,X = 7 (6502: 6). JSR/RTS = 6 and
PHA/PLA = 3/4 match real silicon, as do all zp/zp,X/zp,Y/abs/abs,X/abs,Y
load-store forms.

### 4.2 Instruction stream (and what "1504 fetches" does and does not mean)

1504/1504 aligned fetch pairs identical (opcode + address). No wrong
instruction was ever executed by either core.

**The 1504 fetches are not 1504 distinct instruction cases.** 766 are
non-park fetches, each at a **distinct address** (the directed program
region $0500–$0912 contributes 760; the two interrupt-handler routines at
$1020/$1030 contribute 6), and the remaining **738 are all repetitions of
the single self-`JMP $0908` park instruction** (`4C 08 09`; first park
fetch: G cycle 1788, N cycle 1786). The park repetitions are load-bearing
for the equivalence claim only in that they prove both cores keep taking
the same path through the loop to the end of the trace; per-instruction
coverage is the 766 distinct non-park fetches.

### 4.3 Memory and end state

- **Final write-map equality**: identical final images at all 33 distinct
  written addresses (Step 5). This is a final-value check, not transaction
  equality.
- **Ordered write events** (`semantic_compare.py`): G 98 rows vs N 70;
  the difference is exactly the 28 whitelisted RMW old-value pre-writes
  (§4.1), zero unwhitelisted divergences.
- End-of-trace registers: PC, SP, A, X, Y and flags N,V,D,I,Z,C all equal in
  both cores (both sit in the final self-`JMP $0908` park loop, SP=`$F7`,
  I=1 — the handlers returned via explicit JMP long before cycle 4000).
  Only `P_B` differs — see 4.4.

### 4.4 Interrupts and the B flag

IRQ@730 and NMI@768 are handled identically: same stack bytes pushed
(IRQ: `06 E3 E0`; NMI: `07 01 64`), same vectors read (**IRQ `$FFFE/$FFFF`
→ `$1020`** — verified in the trace, G cycles 736/737; the earlier
"$FFFC/$FFFD" in this section was wrong, that is the RESET vector — and
**NMI `$FFFA/$FFFB` → `$1030`**, G cycles 775/776), same SP trajectory
(`FD→FA→F7`).

Coverage marks: the handlers return via **explicit JMP, so RTI and
interrupt-return are NOT covered by this pair** (Priority 3 gap). The BRK
statements below are **source-level reasoning only** — no BRK is executed
anywhere in this stimulus; a directed BRK test is a Priority 3 item.

The live `P_B` column differs throughout (G=0, N=1) but this is **cosmetic**:

- G has no B register. Its documented model (`R65Cx2.sv` ~line 655): "No
  actual 'B' flag exists inside the 6502's processor status register. The B
  flag only exists in the status flag byte pushed to the stack… when the
  flags are restored (via PLP or RTI), the B bit is discarded." Pushed B =
  `~irqActive` → **1 for PHP/BRK, 0 for IRQ/NMI** (`aluModeP`).
- N also has no B register. `reg_p = {fl_n, fl_v, 1'b1, 1'b1, fl_d, fl_i,
  fl_z, fl_c}` hardcodes bit4 (and bit7) to 1 — that is the constant B=1 in
  its trace. Interrupt pushes use a separate composition with B cleared
  (`int_active`), and `do_writeback(R_P)` restores only N,V,D,I,Z,C — B
  discarded, same as G.

Both cores therefore push **identical bytes in all four scenarios** (PHP→B=1,
BRK→B=1, IRQ/NMI→B=0) and discard B on restore; they merely display the
undriven bit oppositely (0 vs 1). This is consistent with the r65c02
harness, which already skips `P_B` in its equivalence gate ("never driven in
VHDL").

### 4.5 Apparent differences that were ruled out

- SP after PHA `$05A9`, Z after TSB `$0640`, N/C after ASL/ROL.zx `$065E`–
  `$0660`, I at IRQ entry: all ±1-row state-update skew (Step 4), not real.
- DO mismatches on read rows and the RW-only flip rows: sampling artifacts
  (Section 3).

## 5. Interpretation and decision point

N was deliberately built to **W65C02S datasheet** cycle counts (file header;
PLAN_gameKing_core_20260731.md decision 1). G is the FPGA64/R65Cx2 lineage,
whose timing matches real silicon only incidentally. The §4.1 delta (three
opcode classes, six instances) is therefore an expected model difference,
not a bug in N — with one nuance:
on JMP (abs,X), **G** is the one deviating from both real chips (5 vs 6).

Options:

1. **Keep N as-is (recommended, and the policy in force per
   `CPU_COMPARISON_RECOMMENDATIONS.md`).** Document the delta table of §4.1
   as known model differences; keep the maintained gate —
   `semantic_compare.py` + `semantic_whitelist.txt` — on instruction stream
   (fetch identity), ordered write events (whitelist-only), final write-map
   equality, boundary states, and end-state registers — all of which pass
   with every accepted difference named in the whitelist. This preserves N's
   W65C02S fidelity; G's extra old-value write-back on RMW forms matches no
   real silicon.
2. **Force cycle-exact parity with G.** N would need: +1 cycle writing the
   old value on shift/rotate abs,X, −1 internal cycle on JMP (indirect), −1
   indexing cycle on JMP (abs,X). This makes N *less* datasheet-accurate to
   match FPGA64 quirks, and is only worth it if some downstream test requires
   G-exact cycle timing.

## 7. Not covered here

Not covered by the r65 pair (all are Priority 3 directed-coverage items in
`CPU_COMPARISON_RECOMMENDATIONS.md`):

- **BRK** — no BRK in the stimulus; §4.4's BRK/B-flag statements are
  source-level reasoning only.
- **RTI and interrupt return** — handlers return via explicit JMP; RTI
  restoration (including R65Cx2's documented non-standard semantics) is
  untested.
- IRQ while masked, IRQ unmask timing, NMI edge behavior, IRQ/NMI priority,
  nested/adjacent requests.
- Mid-stream reset and reset asserted at different instruction phases.
- `JMP (abs,X)` with nonzero X, page carry, and boundary addresses (the
  covered instance has X=0, no carry).
- RMW targets modeled as side-effecting I/O (an extra write strobe is
  invisible to final write-map equality on plain RAM; a write-strobe counter
  in the TB memory model is needed to make it gate-visible).
- Read-event ordering is **report-only** in the checker (`--report-reads`):
  31/1504 instructions show read-list differences in this trace (24 RMW EA
  re-reads by N, plus STZ dummy-EA-vs-b2-re-read, JMP-indirect extra reads
  matching their `LEN -1` delta, pre-interrupt NOP dummies, and park-tail
  truncation). Not a pass/fail gate while the stimulus is plain RAM.

The other two stimulus pairs run by `run_divergence.ps1` (t65 phase 0:
directed 320-cycle program with IRQ/NMI; t65 phase 1: apple2e ROM boot
walk, 500 cycles) were not re-analyzed in this pass. The same methodology
applies; `analyze_traces.py` Part 2 already cross-correlates their
register-state sequences.
